# Documentação do Sistema Acadêmico

## Estrutura

| Pasta | Conteúdo |
|---|---|---|
| `gerenciamento/` | Plano, riscos, cronograma, processo, backlog, mudanças e relatório |
| `requisitos/` | Levantamento, RF, RNF, rastreabilidade, testes e manual do usuário |
| `uml/` | Casos de uso, classes, sequência e atividades |
| `arquitetura/` | Arquitetura, padrões, modelo de dados e manual técnico | 
| `manutencao/` | Registro de manutenção |

Os papéis acima reproduzem a divisão indicada no `README.md` do projeto. Os nomes dos integrantes ainda precisam ser preenchidos pela equipe.

## Situação e limites das evidências

- O código implementa uma aplicação de terminal, sem API REST e sem login.
- O banco é SQLite e contém sete tabelas.
- A suíte foi executada na cópia analisada: **66 testes passaram** com `unittest`.
- O registro de manutenção ainda é um modelo sem ocorrências preenchidas.
